# 少儿编程 C++ IDE — 项目总纲

> 浏览器端 C++ 在线编程环境，面向少儿教学场景。

## 项目定位

为少儿编程教育提供一个**无需后端**的 C++ IDE：

- 代码在浏览器里**直接执行**（不需要编译服务器）
- 支持**实时调试**（看变量怎么变的）
- 界面友好，错误提示学生能看懂
- 跨设备可用（PC/平板）

## 核心挑战

不是"写个前端页面"——核心是做一件事：**在浏览器里跑 C++ 代码**。

```
正常流程:  源码 → 编译器 → 可执行文件 → OS 执行
本方案:    源码 → 解释器(JS) → 浏览器 Worker → 直接输出
```

C++ 是静态强类型语言，浏览器里跑它需要：
1. **词法分析** — 把文本拆成 Token
2. **语法分析** — 把 Token 组成功能树（AST）
3. **解释执行** — 遍历 AST，模拟 C++ 运行时
4. **标准库** — 用 JS 重写 cout/cin/vector/string
5. **沙箱** — Worker 隔离，防卡死、防崩浏览器

## 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端框架 | React 18 + TypeScript | 类型安全，生态成熟 |
| 构建 | Vite 5 | 开发快，产物小 |
| UI | Tailwind CSS | 原子化样式，快速出界面 |
| 编辑器 | Monaco Editor | VSCode 同款，C++ 语法高亮 |
| 状态 | Zustand | 轻量，无 boilerplate |
| 解释器 | JSCPP（Phase 1-3）→ 自研（Phase 4） | 先跑通验证，再做深度定制 |
| 沙箱 | Web Worker | 隔离执行，超时可控 |
| 测试 | Vitest | Vite 原生，速度快 |

| 阶段 | 做什么 | 为什么 |
|---|---|---|
| Phase 1-3 | JSCPP 二次开发 | 1 周跑通全链路，验证架构可行；UI/调试器/Worker 通信都可以基于 JSCPP 开发，不浪费 |

## 关键设计决策

### 1. 为什么用 Web Worker？

- **沙箱隔离**：Worker 有独立的 JS 执行上下文，代码崩溃不影响页面
- **超时可控**：`setTimeout` 在主线程检测 Worker 是否超时，然后 `worker.terminate()`
- **不阻塞 UI**：解释执行是同步的，如果放主线程会卡死页面

### 2. 为什么先 JSCPP？

- JSCPP 是一个用 JS 写的 C++ 解释器（2.0.9 版）
- 支持基础语法：变量、条件、循环、数组、函数、指针、位运算
- 不支持：`vector`、`string`、`struct`、模板、步进调试
- 用它可以在 1 周内跑通"写代码→执行→显示输出"的全链路

### 3. 为什么自研而不是继续用 JSCPP？

JSCPP 的局限：
- **同步执行**：`JSCPP.run()` 阻塞到执行完，无法在中间暂停
- **无 AST 暴露**：不能遍历 AST 做步进、断点、高亮
- **标准库有限**：只有 iostream/cmath/cstdlib 等，缺 vector/string/algorithm
- **无错误行号解析**：错误消息格式不稳定，只能正则猜测

自研可以做：
- 每个 AST 节点执行前检查断点 → **步进调试**
- 维护作用域链 → **实时变量快照**
- 定义清晰的标准库接口 → **vector/string/algorithm 全部支持**
- 结构化错误 → **精确到行列号 + 友好提示**

### 4. 为什么不用 WebAssembly？

WASM（如 Emscripten 编译）性能更好，但：
- **不是解释执行**，是编译后的机器码，调试体验完全不同
- **启动慢**：需要下载 WASM 模块（几 MB）
- **调试器难做**：WASM 的调试工具链不成熟
- **教学不适合**：学生看不到"一行行执行"的过程
